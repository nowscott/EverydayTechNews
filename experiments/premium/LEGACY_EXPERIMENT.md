## 安装与运行

在项目根目录运行（示例数据目录默认premium_data）：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python experiments/premium/brief.py collect
.venv/bin/python experiments/premium/brief.py sample
.venv/bin/python experiments/premium/brief.py work --issue sample-2026-10-18
.venv/bin/python experiments/premium/brief.py render --issue sample-2026-10-18
.venv/bin/python experiments/premium/brief.py status
```

密钥用环境变量 `DEEPSEEK_API_KEY` 注入。可从密码管理器或权限受限且在仓库外的环境包装器载入，避免把值放进命令历史、crontab、输出、Git。远端自建运行器可使用同名仓库 Secret，但本次未创建/修改 Secret、未配置远端任务。工具不继承普通版邮件/Notion密钥。不要用打印环境变量的方法排错。任务命令不支持传入执行时间或跳过门禁。

`sample` 创建不可变输入快照，默认20篇；`daily` 创建上海当天05:00截止的最近24小时候选，最多8篇，不足5篇显示不足，不凑数。每期最多8条展示在邮件中；完整20篇样本都在对照表中。

```sh
.venv/bin/python experiments/premium/brief.py daily
.venv/bin/python experiments/premium/brief.py work --issue 2026-10-19
.venv/bin/python experiments/premium/run_trial.py init --start 2026-10-19
.venv/bin/python experiments/premium/run_trial.py tick
.venv/bin/python experiments/premium/run_trial.py report
```

上述init已在本地执行，重复init会拒绝覆盖。tick限定七个自然日；样本未审阅时先尝试恢复样本生成，等待人工审阅标记后才创建当天冻结版本并尝试生成；窗口外只保留任务。`report`列出缺期、已选、已生成和可发送数；不会把有草稿算作已完成人工审阅。试刊每天：全天采集 → 05:00冻结最近24小时 → 低价窗口生成 → 审阅对照表记录事实错误/无依据陈述/遗漏/修改 → 留存版本。人工填写CSV保存为新文件；不要覆盖原证据。后续生成不导入CSV为“机器事实保证”，也不启用发送。

冻结后的新文章进入下一期；同名重跑不会改变已冻结输入。如要纠正选题或重核规则，用新issue名创建新快照；已完成且输入未变化的结果仍复用。错过截止后的历史队列会在试刊计划内的下一有效窗口排在当天任务之后恢复，也可显式执行 `work --issue 旧期号`，仍受有效窗口限制；输出标记 delayed_generation，不算按时试刊，不混入新期。

## 排序、去重与更新

实验先排除促销、旧闻、未来发布时间、截止后抓到的信息与不足正文；按可解释主题优先（AI、芯片、产品/更新/行业优先于其他科技）、发布时间排序，样本还兼顾类别。它不是全网重要性排名，发布前仍需人工选题。

URL/正文指纹去重；标题相似及带数字的产品名、RTX Spark等跨语言产品词用于同事件聚类。相似事件先留一篇，疑似重复列入排除/待审记录；启发式可能误合并或漏合并，特别是没有共享产品词的中英文报道，不能宣称语义去重完美。同一URL多版本优先最新观察；跨期同事件内容变化保留旧文证据并标记 update_review_required，人工核实是否有新增事实。已收录事件的旧发布时间文章若最近24小时观察到正文变化，会明确标记“旧文近期内容变化待审”，模型同时收到旧文证据以只提取新增事实；不能声称它是新发生的事件。内容更新不自动被当作已确认的新事实。

## 所有真实请求的门禁与费用

[DeepSeek中文官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)于2026-10-18重新核实：deepseek-flash（DeepSeek-V4.1-Flash-1017）空闲价每百万token输入缓存未命中1元、命中0.02元、输出4元。非思考写作，JSON输出，不使用Search/Fetch或工具；不自动升级模型。

官方高峰为北京时间工作日（排除中国法定节假日）09:00–12:00和14:00–18:00，其余空闲。实验仅允许每天05:00–06:15，全天都与这些高峰不相交，不依赖节假日历。旧00:30–08:30规则没有采用。

policy.json保留规则来源、核实日、有效期（本轮至2026-10-26 00:00上海时间）、模型版本、价格、提示词版本及预算。有效期是本实验设置的复核期限，不是官方承诺价格不变。每次付费调用前重新获取官方页面并核对模型版本、表格对应列价格和峰谷规则；无法获取、变价、配置冲突、过期即暂停，记录last_rule_check。规则有效也不能跳过时间检查。

`paid_request`是唯一模型POST位置，人工命令、重试、后续核对/修复若添加都必须从这里调用，禁止新增旁路。当前没有单独的付费模型复核/修复流程。工作入口检查时间，实际发出前再检查：05:00开始，06:12起拒绝新请求（结束前180秒余量）；请求总deadline90秒，网络连接10秒、读60秒，保留60秒以上余量。该机制只能控制客户端请求，**不能仅凭发起时间或客户端取消保证服务端完成/计费时间**；最终费率和账单仍需对账。

SQLite持久化加文件锁串行化全部本地命令；预算在发出请求前提交预留。默认每日上限2元，可配置。按UTF-8字节数加512输入开销、最大1800输出token保守预留，完成后记录API实际usage、调用次数、耗时和按价格估算费用；估算不代表账单实付。未知usage保留全额预留，不乐观归零。

超时/断网/中途退出的请求可能已计费：inflight或uncertain_requires_review暂停自动重试，保留证据等待人工查看提供方记录。429持久化两分钟退避，下次调度仍经过门禁、预算和次数限制；每条最多3次尝试。格式/证据失败为failed_validation_review，不进入可发送内容、不自动反复付费修复。没有把HTTP错误响应、密钥或请求异常全文写日志。

缓存键包括URL、标题、发布时间、内容指纹、模型名/版本、提示词版本及提示词实际SHA256。完成结果重跑不再调用；输入变化会产生新键；模型/提示词变更后旧队列拒绝混用，需新issue。未知费用的失败无法承诺“恰好一次计费”，所以暂停自动重发，不能切换高价抢进度。

典型假设每条4000输入+800输出，无缓存折扣：每条0.0072元，20篇0.144元，每日5–8条0.036–0.0576元，七期约0.252–0.4032元。本次20篇真实输入按字节保守预留一轮约0.219元，若每篇都三次约0.656元；实际长度/重试会变化，每次都重新检查预算。详细参数见premium_data/cost-estimate.json，真实usage尚未取得。

## 调度启停与持久化

crontab.example只是模板，不在.github/workflows中，不会因提交而启动。本次没有安装crontab或launchd任务，没有发布部署。

模板假设运行器时区为UTC：前一天21:00=上海当天05:00；每小时:45采集，使04:45观察可用于05:00冻结；21:10至22:10 UTC分次唤醒用于有限重试。若机器使用上海时区，应将生成任务换成05:00及05:10…06:10，采集时间不变。别在macOS本地上海cron里原样使用UTC模板；CRON_TZ并非所有cron实现支持。

## 订阅规模与边际成本

“同一期内容生成一次，让所有订阅者复用”具有低边际生产成本，不是低边际效益。当前模型缓存键只与文章/模型/提示词相关，不包含订阅者；邮件发送不调用模型，因此从1位读者增加到1万位读者，同一期AI精编费用不会乘以1万。本次约0.129元是20篇含修复的实验生产成本，不能直接当作未来每期固定报价。

总费用仍包括：每期采集与编辑/模型费用＋投递封数×单封费用＋数据/存储/送达率维护＋可能的按订阅人数收费的平台或内容授权。每天生产新一期仍有新的编辑/模型费用；若以后做个性化内容，费用随“不同内容版本数”增加，不能为每名订阅者无条件重新调用模型。

以[Amazon SES当前官方按量价](https://aws.amazon.com/ses/pricing/)为示例，基础发信0.10美元/千封，1万封约1美元/期，每天一封、30天约30美元/月；数据和附加功能另计。官方默认Essentials套餐当前为0.16美元/千封，对应约48美元/月基础发信。两者只是不同套餐的比较示例，不是本项目现有SMTP的报价，也不是总费用承诺。当前个人SMTP只验证了两封指定测试邮件，没有证明能稳定发送1万封。

商业价值还需要试刊验证选题、准确性、节省时间和续订意愿，低模型成本本身不代表用户愿意付费。
